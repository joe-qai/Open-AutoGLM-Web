三、ScriptExecutor — 子进程脚本执行器
这是你问的核心。方案非常直接：subprocess.Popen 启动子进程跑 .py 文件。
3.1 执行流程
start(script, device, project)
  │
  ├── 构建环境变量: DEVICE_SERIAL=xxx, APP_PACKAGE=xxx
  ├── command = [sys.executable, script.file_path]
  ├── Popen(stdout=PIPE, stderr=PIPE, text=True, env=env, cwd=脚本目录)
  └── 返回 Popen 对象（不阻塞）
wait(cancel_check)
  │
  ├── 启动stderr读取线程（daemon）
  ├── 主线程逐行读stdout（readline + 非阻塞轮询poll）
  │   ├── 每行写入self.logs（带时间戳+级别）
  │   └── 每次循环检查cancel_check() → True则process.kill()
  ├── 等待进程结束
  ├── 解析exit_code: 0→success, 非0→failed, killed→cancelled
  ├── 特殊错误检测: ModuleNotFoundError → "xxx未安装！"
  └── 返回 {status, logs, stdout, stderr, exit_code, duration_ms}

3.2 关键设计点
① start/wait 分离（非阻塞生命周期）

# 不阻塞，拿到Popen后可以做别的事
proc = executor.start(script, device, project)
# 需要结果时再wait，支持传入cancel_check回调
result = executor.wait(cancel_check=lambda: dispatcher._is_cancelled(task_id))



这样做的好处：
可以在 start 后跟踪进程（_track_process）
可以在 wait 中实现取消检查
支持异步日志推送（虽然当前实现是同步的）
② 环境变量注入（设备信息传递）

env["DEVICE_SERIAL"] = device.serial    # ADB设备序列号
env["APP_PACKAGE"] = project.app_id     # 应用包名（可选）



脚本内部通过 os.environ["DEVICE_SERIAL"] 获取设备信息，零耦合——脚本不需要import任何平台代码。

③ 逐行读取stdout（实时日志）

while True:
    if cancel_check():
        self.process.kill()
        break
    line = self.process.stdout.readline()
    if not line:
        if self.process.poll() is not None:
            break
        continue
    stdout_lines.append(line)
    self._log(line.rstrip(), "STDOUT")



不是等进程结束后一次性读取，而是边运行边读，每行立即记录到logs。

④ stderr 独立线程读取

def read_stderr():
    for line in self.process.stderr:
        stderr_lines.append(line)

stderr_thread = threading.Thread(target=read_stderr, daemon=True)
stderr_thread.start()



防止stderr缓冲区满导致进程阻塞。daemon=True，主进程退出时自动清理。

⑤ 智能错误解析

def _parse_stderr_error(self, stderr: str) -> Optional[str]:
    match = re.search(r"ModuleNotFoundError: No module named ['\"](\w+)['\"]", stderr)
    if match:
        return f"{missing_module}未安装！"



不只是报exit code，还能从stderr中提取人类可读的错误提示。

四、AndroidExecutor — 关键字驱动执行器
本质：uiautomator2 直连设备，按步骤逐个执行关键字。
4.1 执行流程
run(test_case, device, project, db)
  │
  ├── u2.connect(device.serial)        # 连接设备
  ├── d.app_start(project.app_id)       # 启动被测APP
  │
  ├── for step in test_case.steps:      # 逐步骤执行
  │   ├── 从DB查keyword名称
  │   ├── 从DB查PO元素定位器
  │   ├── 解析params (JSON)
  │   ├── _execute_keyword(d, kw_name, locator, params)
  │   │   ├── 内置30+关键字 (click/input/swipe/assert/...)
  │   │   └── 自定义关键字 (custom_keyword_loader动态加载)
  │   ├── 每步截图
  │   └── 失败即停止（break）
  │
  └── 返回 {status, steps, logs, screenshots, device_info}

五、TaskDispatcher — 任务调度与多设备并发
dispatch(task_id)
  │
  ├── 查任务 → 查用例/脚本 → 查设备列表
  ├── ThreadPoolExecutor(max_workers=len(device_ids))
  │   └── 每个设备一个线程 → _execute_on_device()
  │       ├── 安装APK（如有）
  │       ├── 创建对应Executor
  │       │   ├── script类型 → ScriptExecutor.start() + wait(cancel_check)
  │       │   └── keyword类型 → AndroidExecutor.run()
  │       └── 写入TaskResult到DB
  │
  ├── 汇总结果 → 生成HTML报告
  └── 更新Task状态 (completed/failed/cancelled)



取消机制：

# 1. 设置取消标志
self._cancel_flags[task_id] = True

# 2. ScriptExecutor: wait中检查cancel_check → kill进程
# 3. AndroidExecutor: 没有主动取消（因为u2调用是同步的）
# 4. 进程追踪: _track_process → terminate + kill

# 5. DB状态更新: running → cancelled



进程追踪：

# 记录每个任务启动的子进程
self._task_processes[task_id].append(proc)

# 取消时批量终止
for p in procs:
    p.terminate()
    p.wait(timeout=3)  # or kill()

核心特点：子进程隔离执行 + 环境变量零耦合 + cancel回调 + 动态关键字加载。方案务实，没有过度设计。

不足： WebSocket实时日志未和Executor打通；AndroidExecutor无取消机制；截图存储在本地文件系统没有清理策略。

一句话：用最朴素的方式（subprocess）解决脚本执行问题，用uiautomator2解决关键字驱动问题，两者通过BaseExecutor统一接口，TaskDispatcher统一调度。 🦞
